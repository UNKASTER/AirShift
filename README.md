# 航勤智排（AirShift）

面向航司地服人员的 Android 排班助手。应用在手机本机识别排班图片或 `.xls` / `.xlsx` Excel 文件，只提取当前用户的保障航班，并由手机直接调用飞常准 Aviation MCP 获取实时动态。项目不需要服务器、云函数或自有域名。

## 已实现

- 界面采用中国东方航空 VI 风格（东航红仅作标识点缀/主按钮/出港标签，藏青标题 + 云白底 + 白卡微边框弥散阴影的「安静的效率感」设计），底部标准三段导航：全部执勤 / 当前执勤 / 设置。
- 全部执勤页沿用原有任务列表；特服只显示小角标，登机口/机位变更仅显示“变更”最小提醒元素，实际变更值在当前执勤页展示。
- 当前执勤页显示正在执行任务的到位倒计时（进港：实时到达前 10 分钟；仅出港：实时起飞前 1 小时）、登机口/机位变更的新旧值对比、出港预计登机开始（起飞前 40 分钟）与预计登机口关闭（起飞前 15 分钟，均以实际起飞时间为准回退预计/计划）、完整特服详情；执勤完成按钮按日推进任务进度，并自动跳过已结束任务。手动进度存于本机，跨日和新排班导入时重置，普通实时刷新不重置。
- 首次启动询问姓名并永久保存在本机，设置页中可修改。
- Android 系统图片选择器导入排班截图，不申请整个相册权限。
- PP-OCRv6 tiny + ONNX Runtime 离线中文 OCR；按表头锚点分列、按 Y 坐标聚类还原数据行。
- Android 系统文件选择器导入 `.xls` / `.xlsx` 排班；按文件签名识别格式、按表头语义定位列，兼容日期标题行、照片附加列、`接送机人员` / `送机人员` 等表头变体、紧凑模板、文本或数值时间及 `+` 次日标记。大型 `.xls` 使用事件流方式读取，临时文件仅存放在应用私有缓存中，并限制为 256 MB。
- 可通过 Android 标准文件分享接收 WPS 的单个 `.xls` / `.xlsx` 排班；首次使用会先完成姓名设置再继续导入，不接收 WPS 云链接或多文件分享。分享队列保留重复文件事件，并在系统重建后恢复尚未完成的导入；具体 WPS 版本的兼容性仍需真机验证。
- 自动清理航班号中的 `&`、`#` 等符号，并将误识别的 `CES` 航班前缀规范为 `MU`。
- 姓名规范化后按完整姓名匹配，并支持同组人员组合签名；不使用单字 OCR 模糊匹配。
- 仅从截图右侧 VIP 区域提取航班号，并标记当前用户实际执勤的 VIP 航班；不展示或保存人员信息及其他附加栏目。
- 显示机号、机型、进出港航班、机场三字码与名称、计划与实时时间；登机口、出发机位挂在始发站下方，到达站机位挂在到达站下方。
- GPS 与当日航班两端机场坐标比对，15 km 内自动判断当前机场。
- 提醒规则：
  - 有进港航班（包括进港后接续出港）：只在预计落地前 10 分钟提醒；
  - 仅出港航班：预计起飞前 1 小时提醒。
- 预计时间变化后重排闹钟；应用前台每 5 分钟、后台每 15 分钟，仅刷新当前执勤与下一项未完成执勤。导入后的首次查询和有未完成执勤时的手动刷新也使用同一窗口，不再按计划时间的前后小时数筛选。
- 每项执勤包含其进港和出港航班，按航班号与日期去重，两项窗口每轮最多查询 4 个航班。点击“执勤完成”后窗口前移，仅立即补查新进入窗口的航班；正在刷新时保留并合并补查需求。普通刷新不重建后台周期任务。
- 手动完成的任务与自动完成的任务共同决定执勤进度；自动规则为已有实际时间，或预计/计划时间超过 3 小时（无可用时间的航段视为完成），过站需两段都完成。全部完成后停止前后台自动刷新，但“全部执勤”页手动下拉仍可查询全部排班航班并更新数据，不重置完成进度。此时只有主动下拉才触发全排班查询，仍保留缓存、去重与限流；导入新未完成排班后自动恢复。窗口外任务平时显示导入数据或最后一次实时数据，提醒沿用这些时间。超长延误仍可能被原有完成规则跳过；手动查询若修正预计时间而使任务重新未完成，自动刷新会按原规则恢复。
- 相同航班与日期的查询在手机端缓存 120 秒，并设置每分钟 30 次的进程级调用保护。
- 飞常准 API Key 由用户在设置页中手动输入，可测试连接或随时清除。
- 经用户主动授权后，仅监听 MUC（`com.ceair.im.muc`）新通知，在本机识别特服、登机口/机位变更、放弃服务和取消行程；航班按数字部分精确匹配当前排班。
- 高置信特服直接关联航段；未导入对应排班时最多等待 24 小时并在排班变化后自动重试，低置信消息直接忽略，不再进入人工确认。
- MUC 登机口与机位变更独立覆盖航段卡显示，取消消息按时间停用对应特服或整段行程，旧摘要不能恢复已取消记录。
- 开机后恢复排班提醒。

## 本机环境

- Android Studio Quail 3（2026.1.3.7）
- Android SDK 33 与 37，最低支持 Android 13（API 33）
- Gradle 9.5.0（国内镜像下载，使用官方 SHA-256 校验）
- Kotlin 2.4.10 / Jetpack Compose

由于项目位于 OneDrive，本机生成目录通过忽略的 `local.properties` 放在 `%LOCALAPPDATA%/CodexBuild/AirShift`，避免同步程序锁定 Gradle 中间文件。

## 飞常准端侧直连

应用仅供个人安装使用。用户在设置中手动输入自己的飞常准 API Key；手机通过 HTTPS 直接请求飞常准 Aviation MCP 的 `searchFlightsByNumber` 工具，不经过任何自建服务。

API Key 使用 Android Keystore 管理的 AES-GCM 密钥加密后保存在应用私有存储中，明文不会进入 saved-instance-state。设置页提供“测试连接”和“清除 API Key”；清除后会同时停止后台实时刷新。项目不会在源码、资源、`BuildConfig`、`local.properties`、测试样例、Git 或 APK 中预置共享密钥。

为保护个人 API 配额，应用进程内对同一航班与日期缓存 120 秒，并保留每分钟 30 次查询保护。一次刷新中的重复航班与日期只会发起一次请求；前台与 WorkManager 共用同一缓存和限流状态。

已实测 `searchFlightsByNumber` 的字段映射：

| 应用字段 | 飞常准字段 |
|---|---|
| 计划起飞/到达 | `FlightDeptimePlanDate` / `FlightArrtimePlanDate` |
| 预计起飞/到达 | `VeryZhunReadyDeptimeDate`、`FlightDeptimeReadyDate` / `VeryZhunReadyArrtimeDate`、`FlightArrtimeReadyDate` |
| 实际起飞/到达 | `FlightDeptimeDate` / `FlightArrtimeDate` |
| 登机口关闭（近似） | `EstimateBoardingEndTime` |
| 实际离位 | `FlightOutgateTime` |
| 出发/到达机位 | `DepStandGate` / `ArrStandGate` |
| 廊桥属性 | `arr_bridge`（回退到 `bridge`） |
| 机场定位 | `DepAirportLat/Lon`、`ArrAirportLat/Lon` |

## 隐私与限制

- 姓名、排班及图片/Excel 识别结果只保存在设备本机；原文件不会上传。实时刷新时只向飞常准发送航班号、日期及 Aviation MCP 协议所需字段。
- 飞常准 API Key 只在用户设备上加密保存并作为 `X-API-Key` 请求头发送给飞常准；应用不会记录密钥、完整请求头或原始敏感错误响应。
- VIP 区域只生成当前用户任务上的布尔标记，原始文字不会持久化；旧版本保存的附加信息会在新版启动时删除。
- 定位仅在本机用于匹配排班相关机场。
- MUC 通知正文只在内存中解析；持久化仅包含航班、日期、结构化结果和不可逆指纹，不保存原文、姓名、发送人、电话、票号、座位、图片或附件。
- Debug APK 使用调试签名，仅用于开发验证。个人正式安装前仍需配置发布签名，并自行遵守飞常准服务条款与 API 配额限制。
